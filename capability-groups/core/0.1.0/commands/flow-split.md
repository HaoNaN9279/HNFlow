# `/flow-split` — 需求拆分，不落笔

用户需求：$ARGUMENTS

本命令**只产出方案**：不写流程定义、不建能力组、不调用 `create` / `draft`。

## 步骤

1. 加载技能 `flow-intake`：抽出目标、触发方式、启动输入、最终产物、验收标准、人的介入点、失败处理、频率、复用范围。缺关键项先问，最多 3 轮；其余标注为“假设”。
2. 加载技能 `flow-boundary`：按 8 个判定问逐条分类，产出两张清单。
3. 自检：有没有把“怎么做”写进流程、把“什么时候做”写进能力组或流程、把权限当流程。

## 输出格式

```text
## 1 需求摘要（含假设）
## 2 边界表
| 内容 | 归属 | 理由 |
| --- | --- | --- |
（流程节点 / 能力组规则·技能·人设 / 项目文件（含 `.hnflow/triggers.json`）/ 启动输入 / 模型层）
## 3 流程草案（文字版，不写 JSON）
节点序列 + 每个节点的一句话契约 + 门禁与人工交付点 + 起点终点
## 4 配套能力组草案
组名、目录、每个文件一行职责、激活步骤
## 5 待确认
```

结论必须标：**可进入 `flow-new` 实施** / **需补信息**。
