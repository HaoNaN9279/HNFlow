# 边界拆分（Boundary）

一句话：**能力组装“怎么做”，流程装“何时、谁、拿什么、交什么、谁验收”。** 拆错方向，后面怎么改都别扭。

## 7 个判定问

按顺序问每一块内容，第一个“是”即为归属：

| # | 问题 | 归属 |
| --- | --- | --- |
| 1 | 这一步需要模型来写/判断吗？ | 否 → `merge`（确定性汇合/常量）、`gate`（人裁决）、`request`（人交付）、`verify`（插件验收） |
| 2 | 这步需要**只有人能给**的东西吗（授权、真实资产、手感、现实判断）？ | 是 → `request`（+`verify`），或 `gate`（只需一个决定） |
| 3 | 这个产物要被下游消费吗？ | 是 → 必须声明节点 `output`，必要时写边 `accepts` |
| 4 | 这段知识/规则会在别的流程复用吗？ | 是 → 能力组 `rules/` |
| 5 | 这套操作步骤会在别的流程复用吗？ | 是 → 能力组 `skills/` |
| 6 | 只有本项目成立的约定（目录、命名、发布规则）？ | 是 → 项目文件（`AGENTS.md`、`docs/`） |
| 7 | 只是这次运行的数据？ | 是 → `flow.input` 或 run `input` |
| 8 | 只是“什么时候自动启动”（定时 / 文件变化 / 上一个流程完成）？ | 是 → 项目文件 `.hnflow/triggers.json`（人写）；流程定义里不表达触发 |

模型路由（`model` 层）与人设（Agent）都不是内容：前者只写层 id，后者只影响会话系统提示，**都不是流程节点**。

## 反模式

| 反模式 | 症状 | 正确做法 |
| --- | --- | --- |
| 领域知识塞进 `instruction` | 同一段规范在多条流程里复制，改一处漏三处 | 提到能力组 `rules` 或 `skills`，instruction 只写“按 X 技能执行 + 本次参数” |
| 用流程表达权限 | 想限制某节点能改哪些文件 | 流程不做权限；用子会话权限与项目规则 |
| 用一个 `gate` 代替验收 | 人肉逐条比对产物 | 机械部分 `verify.checks` + 独立 `judge`，人只裁决“要不要接受” |
| 一个 `agent` 节点干多件事 | 产物一个 schema 装不下，或验收没有标准 | 一节点一产物，拆开 |
| 生产者也当验收者 | 同一个 preset 既写又评 | `judge` / `verify.judge` 换 preset（校验会报 `judge-same-as-producer`） |
| 给 `gate` 画回边做“驳回重做” | 想回到上一步重来 | 流程**无环**：驳回走 `onReject`（插件内重试），或新增“修订”节点向前走到汇合点 |
| 用流程编排工具调用 | 一条流程里塞十几个 shell 步骤 | 工具步骤是能力组技能的事；流程只留需要契约与验收的节点 |
| 把“AI 自评”当验收 | 节点 `done` 就往下走 | `done` 只表示产物满足 schema；还需 `judge` / `verify` / `gate` |
| 把定时/事件触发写进流程 | instruction 里写“每周一自动跑”“文件变了就跑” | 触发是 `.hnflow/triggers.json` 的事（人写）；流程只描述一次运行内部的顺序 |
| 让自动化绕过人 | 以为触发器能把门禁/交付自动过掉 | 触发器只新开 run；`gate` / `request` 仍要人处理，只是会出现在收件箱 |

## 两个典型两难

1. **“这一步要不要人？”**
   人必须提供**输入**（素材、授权、真实文件）→ `request`（有交付物 schema，可被 `verify` 验收）。
   人只需要**做一个决定**（过 / 不过 / 改）→ `gate`。
   两者都不要混：`gate` 不产出交付物，`request` 不产生产出决定。

2. **“属于能力组还是项目文件？”**
   别的项目拿去也有用 → 能力组；换项目就不成立 → 项目文件。判据是“换一个仓库还对不对”。

## 输出格式

```text
## 边界表
| 内容 | 归属 | 落点 | 理由 |
| --- | --- | --- | --- |
| 稿件评审标准 | 能力组 | rules/xxx.md | 跨流程复用 |
| 三方向概念产出 | 流程 | agent 节点 concept | 需要模型 + 产物被下游消费 |
| 精修稿 | 流程 | request 节点 | 需要真实美术判断 |
| 周报字段定义 | 项目文件 | docs/… | 仅本项目成立 |

## 流程清单（节点级）
node: 类型 / 一句话职责 / 输入 / 输出 / 是否人工

## 能力组清单（文件级）
组名@版本：group.json + 每个 rules/skills/agents/commands 一行职责

## 边界风险
- 依赖但未验证的前提（缺能力组、缺模型层、缺 preset）
```

## 交付判据

边界表里每一条都能回答“为什么放这里”；流程清单里没有“怎么做”的长篇说明；能力组清单里没有“什么时候跑”。
