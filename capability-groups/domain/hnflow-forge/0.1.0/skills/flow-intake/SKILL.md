# 需求采集（Intake）

把“想做点什么”变成可编排的结构。产物是**需求摘要**，不是流程定义。

## 采集项

| 项 | 问法 | 缺失后果 |
| --- | --- | --- |
| 目标 | 这件事完成后，什么状态才算“做完了”？ | 终点节点无法确定 |
| 触发 | 谁来启动、什么时候启动：手动 / 定时（cron）/ 文件变化 / 上一个流程完成？ | 不知道 `flow.input` 里该有什么；后三种还需人写 `.hnflow/triggers.json` |
| 启动输入 | 每次运行时必须提供的字段有哪些？可否用假数据跑一遍？ | `input` schema 写不出来 |
| 最终产物 | 交付物是什么形态（文本/代码/文件/结论）？给谁用？ | `output` 契约含糊，下游无法消费 |
| 中间产物 | 是否有人要中途审阅/确认的东西？ | 门禁位置错误 |
| 验收标准 | 谁判定合格？依据什么？能否写成检查项？ | 会退化成“生成者自报完成” |
| 人的介入点 | 哪些环节**必须由人**给出（授权、真实资产、手感、现实判断）？ | 把该人做的事塞给模型，运行必卡 |
| 失败处理 | 某步失败/不达标时，重试、换路、还是停下来问人？ | `onReject` / `onFail` 缺失 |
| 频率与规模 | 一次性、每天、还是很多人用？ | 该建项目草稿还是通用资产 |
| 复用范围 | 只这一个项目用，还是别的项目也要用？ | 作用域选错 |
| 现有资产 | 已有流程/脚本/能力组能复用什么？ | 重复造轮子 |

## 停问规则

- 最多 **3 轮**提问；每轮把相关问题一次问完。
- 能从工作区自查的不问（仓库结构、已有 `.hnflow/stack.json`、现有流程）。
- 用户说“你定”或问题非阻塞时：给缺省值，写进**假设清单**，继续。
- 阻塞型缺口（谁是验收人、输入字段、最终产物形态）必须问清，不能假设。

## 输出模板

```text
## 需求摘要
- 目标：
- 触发与频率：手动 / 定时 / 文件变化 / 流程完成之后（后三种由人写 `.hnflow/triggers.json`）
- 启动输入：字段清单 + 类型
- 最终产物：形态 + 使用者
- 中间产物与审阅点：
- 验收标准：可检查的条目
- 必须由人提供的：
- 失败处理：
- 复用范围：项目内 / 通用

## 假设（未经用户确认）
- …

## 待确认（阻塞项）
- …
```

## 边界提醒

- 采集阶段**不要**开始写 JSON、不要调用 `create`。
- 不要把“用什么工具/什么模型”当成需求；那是实现细节，属于边界拆分与能力组。
- 用户的描述里若出现“AI 自动判断合不合格”，追一句：由独立判定还是由人生成？这决定 `judge` 还是 `gate`。
