# 接入锁步帧同步

## 工作流

1. **确认需求**：是否需要确定性同步（对战、RTS、格斗）。弱同步（各自演算）不需要锁步。
2. **初始化**：Driver 的 `InitializeFrameSync()` 已创建 `LockstepManager`（默认 15 Hz、缓冲 3 帧）与 `FishNetMessageBus`。
3. **调参**：按网络条件调整帧率与缓冲；两端必须一致。
4. **改逻辑时间**：所有玩法逻辑读 `HNLogicTime.Time`，不读 `Time.deltaTime`。
5. **清非确定性**：随机数换 `HNRandom`，浮点判定换定点，遍历顺序固定。
6. **验证**：双端各跑 10 分钟，逐帧比对关键状态哈希。

## 帧率与缓冲

| 参数 | 影响 |
|---|---|
| 帧率低（如 15 Hz） | 带宽小，输入延迟高 |
| 帧率高（如 30 Hz） | 手感好，带宽与校验成本高 |
| 缓冲小 | 延迟低，抖动时卡顿 |
| 缓冲大 | 抗抖动，输入滞后 |

## 确定性清单

- [ ] 无 `UnityEngine.Random` / `System.Random`
- [ ] 无 `float` 参与规则判定
- [ ] 容器遍历顺序固定
- [ ] 无物理引擎浮点结果依赖
- [ ] 无 `Time.deltaTime` 参与逻辑
- [ ] 相同输入双端产出相同状态

## 常见错误

| 现象 | 原因 | 处理 |
|---|---|---|
| 双端不同步 | 非确定性来源 | 逐项过清单 |
| 卡顿 | 缓冲不足或丢包 | 加大缓冲 |
| 输入延迟高 | 帧率低 + 缓冲大 | 调参权衡 |
| 断线重连后错乱 | 未重建逻辑状态 | 重连时重放或快照 |

## 使用时机

接联机对战、同步异常排查时加载。
