# 配置表制作

## 工作流

1. **定结构**：在 Excel/Luban 源表里加列，标明类型与主键。
2. **导数据**：用项目既有的导出流程生成 binary 与 C# 数据类，产物放 `StreamingAssets` 或 Addressables 分组。
3. **注册表**：启动流程里 `SheetManager.LoadAllFromBinary()` 之后 `RegisterTable(...)`。
4. **读取**：`GetTable` 拿表，`TryGet` 取行；封装成 `ConfigService` 供业务调用。
5. **引用资源列**：类型设为 `AssetRef`，编辑器里拖资源；被引用资源必须加 Addressables Label。

## 约束

- 生成类不改手写；结构变更改源表再重导。
- 表名唯一，重名注册抛异常。
- 主键类型全表统一，缺失键抛异常——启动阶段失败就是配置错误，不要吞掉。
- 运行时只读，不写回表。
- 表在启动时一次性加载；热更表需要重进流程，不建议运行时替换。

## 常见错误

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动抛"表未注册" | 忘了 `RegisterTable` 或表名拼错 | 核对注册名与导出名 |
| 键找不到 | 主键类型不一致（`"1"` vs `1`） | 统一主键类型 |
| `AssetRef` 解析为空 | 资源没打 Label | 给资源加对应 Label |
| 改了表没生效 | 只改了源 Excel 没重导 | 重新导出并确认产物进包 |

## 验收

- [ ] 表能被业务读到，主键查询正确
- [ ] 引用了资源的列在运行时能解析出对象
- [ ] 表结构变更后生成类已同步
- [ ] 手写的表访问代码集中在一个服务里

## 使用时机

新增/修改配置表、接入 Luban 导出、或排查表读取失败时加载。
