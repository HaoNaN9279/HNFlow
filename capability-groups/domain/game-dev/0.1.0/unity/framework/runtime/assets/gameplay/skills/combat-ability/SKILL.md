# 实现一个技能

## 工作流

1. **属性集**：角色创建时建 `AttributeSet`，按 `Freeze()` → `Initialize()` 顺序初始化。
2. **配置**：技能参数（伤害、冷却、消耗、效果列表）写进配置表，代码只读 id。
3. **门禁**：用 `GameplayTag` 判断可否释放（框架 `AbilitySystem` 无标签门禁，必须自己写）。
4. **命中判定**：用物理模块的射线/重叠查询，或手写距离判定。
5. **结算**：伤害走 `DamagePipeline.Process`；Buff 走 `BuffSystem`。
6. **逐帧**：在角色更新里 `Tick(dt, attributeSet)` 推进 Buff 与冷却。
7. **表现**：结算后发事件，动画/特效/飘字由表现层订阅。

## 数值顺序

`基础值 → 百分比加成 → 固定加成 → 最终修正`。自定义规则插进管线的对应阶段，不要绕过管线直接改最终值。

## 可逆效果

移除 Buff 不回滚属性。需要临时加成的做法：

```text
记录施加前的属性快照 → 施加 → 到期/移除时按快照恢复（或反向应用）
```

## 常见错误

| 现象 | 原因 | 处理 |
|---|---|---|
| 属性加成不生效 | `AttributeSet` 没 `Freeze` | 初始化顺序补上 |
| Buff 到期还留着加成 | 依赖了自动回滚 | 自己记录并补偿 |
| 多角色共用数值 | 共享了属性集 | 每角色一份 |
| 技能无法被标签限制 | 门禁未实现 | 项目侧写判断 |

## 验收

- [ ] 每个角色独立属性集并逐帧 `Tick`
- [ ] 伤害只经管线结算
- [ ] 可逆效果有恢复逻辑
- [ ] 技能门禁由标签查询实现

## 使用时机

新增技能、战斗数值异常、Buff 残留问题时加载。
