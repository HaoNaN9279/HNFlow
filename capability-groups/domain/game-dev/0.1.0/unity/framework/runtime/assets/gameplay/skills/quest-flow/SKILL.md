# 任务流程

## 工作流

1. **配置任务**：任务定义进配置表（id、条件、奖励、前置）。
2. **初始化**：启动时 `QuestManager<TId>.Initialize()`，只调一次。
3. **注册发奖**：`RegisterRewardHandler` 里写金币/物品/经验的发放。
4. **接取**：`TryAcceptQuest(id)`，失败要给玩家反馈（前置未满足/已接取）。
5. **推进**：业务事件（击杀、拾取、到达）触发 `NotifyGameEvent`。
6. **领取**：先查已领取标记，再 `ClaimQuest(id)`，随后置标记。

## 防重

框架的 `ClaimQuest` 先发奖后校验，重复调用会重复发奖。必须自己维护：

```text
Dictionary<QuestId, bool> awarded
if (awarded.TryGetValue(id, out var done) && done) return;
ClaimQuest(id);
awarded[id] = true;
```

标记要进存档，重启后仍然生效。

## 事件推进

- 任务条件与事件类型一一映射，映射表集中维护。
- 一次行为可能推进多个任务，`NotifyGameEvent` 遍历所有活跃任务。
- 进度只在服务端/单机主逻辑推进，UI 只读。

## 常见错误

| 现象 | 原因 | 处理 |
|---|---|---|
| 重复发奖 | 领取无防重 | 加标记并存档 |
| 进度不涨 | 事件类型与条件不匹配 | 核对映射 |
| 重启后任务状态丢失 | 只存了内存 | 任务状态进存档 |
| 多计数任务完成不了 | `MultiCounter` 未实现 | 用多条独立条件模拟 |

## 验收

- [ ] 领取有防重标记且进存档
- [ ] 前置条件、接取上限有校验
- [ ] 进度事件映射集中可查
- [ ] 任务状态可存档恢复

## 使用时机

新增任务、任务系统接入存档、或排查发奖/进度异常时加载。
