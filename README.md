# HNFlow — AI 工作流编排与执行系统

HNFlow 是一套**领域无关的本地桌面端工作流编排与执行系统**，面向软件开发者和 AI 工作流构建者，定位为 AI 时代的「流程管家」。它将 AI 生成、人工操作、专业软件执行串成可复用、可嵌套的自动化流程。

## 功能定位

- **可视化拖拽编辑**：基于 AntV X6 图引擎，支持节点拖拽、连线配置、参数编辑，直观构建复杂工作流
- **AI Agent 对话辅助**：通过自然语言生成工作流、调度执行、监控进度、排查异常，双入口平权自由切换
- **MCP 原生集成**：以 MCP 协议为首选工具连接方式，可接入 Unity、Blender、Git、命令行等外部工具
- **功能组（Capability Group）体系**：按领域以命名空间方式组织 AI 能力，支持语义版本、依赖管理、懒加载，将软件工程的包管理思想平移到 AI 能力管理

## 设计哲学

HNFlow 的所有设计细节，从六层架构到功能组体系，从双入口平权到版本不可变，背后贯穿着五条核心设计哲学。

### 1. 底座哲学：领域无关的工作流底座

HNFlow 坚决不做任何垂直领域的具体业务，只做通用的编排底座。内核层纯 TypeScript 实现，不依赖任何游戏引擎、设计软件或行业逻辑；所有领域能力通过功能组插件化接入；节点体系、执行引擎、存储方案全部通用，可适配任何行业场景。

### 2. 工程哲学：AI 能力的工程化管理

功能组（Capability Group）体系把软件工程经过几十年验证的包管理思想，完整引入到 AI 能力管理中：版本不可变（修改即发新版，旧版本只读保留）、命名空间隔离（工具自动加前缀，从机制上解决冲突）、依赖静态解析（保存时全量分析，把问题拦截在设计阶段）、资源全局唯一（避免同名工具冲突）。

### 3. 协同哲学：人机平权

全自动化是理想，人机协同才是生产级的常态。HNFlow 从设计之初就把人工节点作为一等公民：拥有完整的生命周期（任务描述、产物校验、打回重交、兜底策略），AI 节点的中断与人工节点统一管理，对外层封装透明。桌面原生体验让待办集中管理、上下文自动传递、轻量一键确认，把人工介入的成本降到最低。

### 4. 形态哲学：本地优先的桌面原生

HNFlow 选择桌面端形态，确保数据主权（所有工作流、功能组、产物全部存在本地，无云端依赖）、深度集成（可深度控制本地专业软件、调用系统命令、访问文件系统、做进程级并发控制）与性能可靠（本地执行不依赖网络，长耗时任务稳定）。

### 5. 交互哲学：双入口平权

可视化编辑器与 AI Agent 对话两个入口完全平权，覆盖工作流从创建到运维的全生命周期：从零搭建流程时对话式快速生成初稿、可视化精细调整；日常运行时自然语言发指令、可视化看进度；排查问题时可视化看节点状态、对话式让 AI 分析错误。

## 特色能力

- **三级节点体系**：原子节点（内置）→ 子工作流节点（复合）→ LLM 原子节点（AI Agent），覆盖从简单到复杂的全部场景
- **人机协同一等公民**：人工节点拥有完整生命周期（任务描述、产物校验、打回重交、兜底策略），AI 中断与人工任务统一管理
- **无限层级嵌套**：子工作流支持无限嵌套，循环依赖全链路检测，常用流程可保存为模板
- **断点续跑**：每步执行持久化，程序崩溃后重启可从断点恢复
- **能力按需加载**：功能组只在执行到对应节点时懒加载，缓存复用，不浪费资源
- **版本不可变**：功能组和子工作流模板采用语义版本管理，每个版本只读快照，引用锁定固定版本
- **六层架构**：用户交互层 → 工作流图模型层 → 编排层 → 执行引擎层 → 基础设施层 → 工具适配层，单向依赖，职责清晰

## 技术栈

| 维度 | 选型 |
|------|------|
| 语言 | TypeScript |
| 运行时 | Node.js / Electron |
| 图引擎 | AntV X6 |
| AI 运行时 | LangGraph.js |
| AI 协议 | MCP（Model Context Protocol） |
| 存储 | SQLite + JSON 文件 |

## 开发路线

- **v0.1.x** — 核心引擎骨架（图模型、执行引擎、原子节点、断点续跑）
- **v0.2.x** — AI 节点运行时（LangGraph 集成、统一挂起、并行/循环/异常处理）
- **v0.3.x** — 功能组体系（存储、依赖解析、运行时加载、版本管理）
- **v0.4.x** — 可视化编辑器（X6 编辑器、版本交互、AI Agent 对话）
- **v0.9.x** — 桌面端体验与生态（托盘驻留、异常恢复、功能组生态）
